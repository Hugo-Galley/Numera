# Backend — conventions (FastAPI / SQLAlchemy 2 / Pydantic v2)

Complements the root `CLAUDE.md`. Step-by-step procedures: `numera-backend` skill. Routes and data schema: `ARCHITECTURE.md`.

## Structure and lifecycle

- `app/main.py`: `lifespan` → `run_migrations()` (Alembic; a failure **blocks startup**, no automatic `stamp head`) + `seed_all()` (default categories + system ETF profiles), unless `APP_ENV=test`. It also starts `recurring_transactions_task`: an asynchronous loop (first pass after 10 s, then every hour) that calls `generate_recurring_transactions`, `check_and_generate_pending_salaries`, `refresh_held_prices` (prices of held securities), `refresh_held_etf_profiles` (composition of held ETFs, at most once a week) and `run_notifications` (new Action Center alerts + Sunday summary to ntfy / Telegram, if enabled).
- Routers: organised by domain (`controllers/{budget,comptes,investissement,analytics,systeme}/`, same tree in `services/` and `repositories/`); all in `protected_routers` (`Depends(get_current_user)`) except `health` and `auth`. `controllers/analytics/` aggregates 10 sub-routers under the `/analytics` prefix (`__init__.py`), plus `analytics/diversity.py` registered separately.
- `controllers/deps.py`: `get_db` (one session per request) and `get_current_user` (decodes the JWT, compares `sub` with `admin_username` read from `system_settings`, falling back to `settings.ADMIN_USERNAME`).
- `get_db` exists only once (`db/session.py`, re-exposed by `controllers/deps.py`): one session per request. **Test** sessions: `conftest.py` overrides `get_db` and `get_current_user`.

## Layers (see `ARCHITECTURE.md` § Backend layers)

- Router (`controllers/`): HTTP signature + one service call, nothing else. Service (`services/`): logic, `commit`, business errors. Repository (`repositories/`): queries, no `commit`. Pure calculation: `domain/`. Network call: `integrations/`.
- `tests/garde_fous/test_architecture.py` rejects any new violation (including a controller import from another domain, a `core/` import outside `core`/`models`/`db`, and an import of a missing `app.*` module: a relative import moved as is, often swallowed by an `except`). `scripts/quality/check_code_size.py` rejects any file > 400 lines or function > 80. The baselines (`architecture_baseline.txt`, `architecture_rules_baseline.txt`, `response_model_baseline.txt`, `clock_baseline.txt`, sizes) only go down, CI ("Cliquets" check) refuses to raise them; every endpoint declares a `response_model` (or 204); the clock goes through `core/time.py`; an identical move renames the key without increasing the value.
- Moving code = updating all importers (absolute, relative, local imports, tests and `monkeypatch.setattr` on the old module), with no re-export.

## Code rules

- Types: `make typecheck` (mypy, `backend/mypy.ini`, blocking in CI). `app/domain/` and `app/core/` are strict (zero errors); elsewhere existing errors are capped per file in `scripts/quality/baselines/mypy_baseline.json` (ratchet: never raise it; after a fix, `python3 scripts/quality/check_types.py --write-baseline` to lower it). New code is fully typed.
- **Text language** (`core/i18n.py`): any text the API returns to the user (`insights` titles and advice, scenario labels, alerts, business errors) goes through `tr("domain.subject.field", variable=…)` or `trn(…)` (plural `_one` / `_other`), never through a hard-coded French string. The language comes from the `Accept-Language` header set by `LanguageMiddleware` (the frontend sends the interface language); without a header (MCP server, scripts, background tasks): French. Catalogues `core/locales/{fr,en,es}.json` (flat keys, `{name}` variables): same keys and same variables in all of them (`tests/systeme/test_i18n.py`). An amount in a text: `domain.insights.eur` (follows the language). What is **data** (category name, merchant, stored value, unit code such as `mois`) is never translated: the frontend translates the codes. A new text = a key in every catalogue + an fr/en test. **Format of a number, amount or date in a text**: `format_number`, `format_money`, `format_date`, `format_datetime` (`core/i18n.py`, `FORMATS` table per language), never `if get_language() == "en"`. **Adding a language**: its code in `LANGUAGES`, an entry in `FORMATS`, `locales/<code>.json` (same keys as `fr.json`), the `Literal` of `schemas/notification.py` (`test_i18n.py` checks it), then `make api-contract`. State: migrated are `insights`, FIRE scenarios, the Action Center (all rules), data audit, taxation (wrapper alerts, placement advice, CTO recap), bank reconciliation and reimbursements (leads, refusals and "not found"), the business errors of services (`errors.*` keys, including those that used to be in English and now display in French by default), push notifications and the weekly digest (language persisted in `notify.language`, see `docs/ACTION_CENTER.md`), diversification alerts and score, valuation and import warnings, CSV row errors, MCP refusals and schema validations (`validation.*`); still French are the **data** (default category names, Yahoo sectors and countries, `Non renseigné`/`Sans catégorie`, notes of benefit deposits, logs) and messages relayed as is (`str(exc)`, Yahoo errors). The French of migrated texts stayed identical to the byte (snapshots unchanged); a plural is written `key_one` / `key_other` (identical in French when the text keeps "(s)").
- Lint: `make lint` (ruff, `backend/ruff.toml`: pyflakes, pycodestyle, isort, bugbear, pyupgrade, simplify, comprehensions, perflint, ruff-specific, bandit; every ignored rule carries its reason in the file), blocking in CI. No `# noqa` without a reason written on the line; do not widen `ignore` to make a deviation pass. Exception re-raised inside an `except`: `raise … from exc` (or `from None` to hide the cause on purpose).
- Type arguments and return values. Logger: `from app.core.logging import get_logger; logger = get_logger(__name__)` (never `print`, never a JWT/hash/secret in logs).
- Errors: in a service, raise `NotFoundError` / `BusinessRuleError` (422) / `ConflictError` / `InternalError` (`app.core.errors`, optional `code` + `context` for a structured error); never `HTTPException` outside `controllers/`. `HTTPException` stays reserved to controllers for 401/403 (auth), 413 and 429.
- Models: `Mapped` / `mapped_column`, indexes on `account_id`, `date`, `merchant`, FKs. No business logic in models → `app/services/` (or `app/domain/` if pure calculation).
- Schemas: separate `Create` / `Update` / `Read`, `ConfigDict(from_attributes=True)` on `Read`, `response_model` on every endpoint (no raw `dict`).
- Endpoints are **all synchronous** (`def`, FastAPI threadpool): an `async def` would run SQLAlchemy on the event loop and block every request (`/health` included, with a single worker). A service that waits on the network (`convert_amount`, `get_exchange_rates`, `services/investissement/market`, `etf_profiles`, recurring generation) stays `async` and the controller calls it through `run_async(service.f(...))` (`core/sync_bridge.py`, a loop of its own per thread). Only exceptions: `main.py` error handlers and reading an `UploadFile`.
- External services (Yahoo, Frankfurter): negative cache for 10 min after a failure, circuit breaker `core/circuit_breaker.py` (3 failures → 10 min without a call), quotes fetched in parallel with bounded concurrency. Any new external call follows this model.
- Layered authentication stack: controllers `systeme/{auth,totp,passkeys}.py` = one service call; logic in `services/systeme/{auth,totp,passkeys}.py`, schemas in `schemas/auth.py`. Errors: `AuthenticationError` (401, optional `WWW-Authenticate`), `RateLimitedError` (429, `Retry-After`), `InvalidOperationError` / `ConflictError` / `NotFoundError`; the `DomainError` handler relays the headers. The service receives the request as `Any` (it does not import starlette).
- N+1: relationships as `lazy="selectin"` on models; otherwise `joinedload`/`selectinload` for lists. **Never a query in a loop**: load the batch in one query and match in memory (`domain/`). Large read-only loads (export, matching): query columns, not ORM objects. A composite index is only justified by an `EXPLAIN QUERY PLAN`. An in-memory cache: invalidation on write, generation, deep copy (specification in the `numera-performance` skill). Measurement: `scripts/perf_profile.py`.
- Dates: `app.core.time.utcnow_naive` (naive UTC datetimes in the database).
- `tests/garde_fous/test_migrations.py` requires `alembic upgrade head` to produce exactly the schema of the models (`compare_metadata == []`): any model change without a migration fails the suite. Revision `a9c1e4d7b2f6` catches up historical differences and does nothing on a database created by `create_all`.
- Schema changed → `cd backend && alembic revision --autogenerate -m "..."`, review the migration, commit it. Migrations apply on their own at startup.

## Finance

- Amounts **always positive** in the database; `type` gives the direction. `apply_transaction_to_balance`: `Entree`/`Interets` add, `Sortie` subtracts, `Solde Initial` **replaces** the balance. (`finance.py`)
- Every transaction mutation (create / update / delete / bulk / transfer link / import) → `recalculate_running_balances(db, account_id)`, defined in **`app/services/budget/balances.py`**. Full recomputation in chronological order; **does not commit** (`flush`): the caller commits **once, after** its last recomputation (never "commit, recompute, commit"; `tests/budget/test_balances_service.py` re-reads balances in a fresh session).
- Currencies: `await convert_amount(...)` (`services/comptes/exchange_rates.py`, never commits) / `await get_exchange_rates()` (`integrations/currency.py`). Store `amount` (account currency) and keep `original_amount` + `currency`. Dated conversion by cross rate through the EUR for any pair; without a usable rate `CurrencyConversionError` (→ HTTP 422 via the handler in `main.py`), **never** a 1:1 fallback.
- Positions: `portfolio_holdings` is **derived**. After any investment-transaction mutation or change to the Zero Point inventory (`holding_baseline_items`), call `await rebuild_holdings(db, account_id)` (`services/investissement/holdings/rebuild.py`): inventory + security transactions after `accounts.holdings_baseline_date`, average cost (PRU) as weighted average fees included (position currency), a sale has no effect on the PRU, `cost_basis_eur` at historical rates. Never write `quantity`/`buy_price_avg` directly.
- Valuation: `services/investissement/portfolio/compute.py::compute_portfolio` (steps in `services/investissement/portfolio/`, XIRR/TWR in `domain/performance.py`) (value = positions × price + cash, unrealised/realised gains, XIRR/TWR, curve, reconciliation); an `investissement` account with positions is no longer valued by snapshot (`uses_positions`). `compute_portfolio` is cached for 20 s (`portfolio/cache.py`), cleared on every flush or commit of any session: do not write to the database through a raw connection without calling `cache.invalidate()`. `services/investissement/holdings/replay.py::replay_account` also replays sales (realised gain) and quantity changes.
- Prices: `get_market_quotes(symbols, db=db)` records each quote in `security_prices` (flush: the calling read service commits) and returns the last stored price (`stale=True`) if Yahoo fails; `get_price_on(db, ticker, date)` for a historical price.
- Solde Initial (opening balance): only one per account and chronologically first; centralised check in `validate_solde_initial` (`services/budget/transaction_writes.py`) for create/update, and in the import.
- SQLite: `PRAGMA foreign_keys=ON` is set on every connection (`db/session.py`, also in `conftest.py`): `ondelete` rules are effective. An FK without `ondelete` (e.g. `salary_configs`) requires setting the reference to `NULL` before deleting the target.
- Internal transfers: `is_transfer`, `linked_transaction_id`, `is_transfer_ignored`; a transfer to an `investissement` account can be linked to an `investment_transaction` (`linked_investment_transaction_id`). "Real expenses" KPIs exclude these transfers.
- Markets: `integrations/yahoo_finance.py` queries **Yahoo Finance** (`query2.finance.yahoo.com`, via `httpx`) for security search and quotes, orchestrated by `services/investissement/market/` (`quotes`: cache, storage in `security_prices` through `repositories/investissement/security_prices.py`; `search`; `suggestions`); `services/investissement/etf_profiles.py` fetches ETF composition there (through `yahoo_finance.fetch_composition`) (sectors + top 10 via `quoteSummary`/`topHoldings`, with cookie + crumb; never countries), source per field in `etf_profiles.composition_sources` (`yahoo` / `preset` / `manual`). Together with Frankfurter, these are the only outbound network calls, plus the push notifications the user enables themself (`services/systeme/notifications.py` (channels: `integrations/notifications.py`): configured ntfy server, `api.telegram.org`).
- Salary: `services/budget/salary_generation.py::generate_salary_transactions` (amount: `domain/salary.py::salary_amount`) creates a single `Entree` transaction "Salaire" (`net_salary − remote_days × ticket_employee_share`, no voucher transaction) from `SalaryConfig` and `TelecommutingDay`, then marks `SalaryMonth.is_generated`; idempotent (guard on `salary_recurring_id` + date). Replayed by the background task through `check_and_generate_pending_salaries`, which also regenerates a month within the last 31 days that is marked generated but has no salary entry (`is_salary_recorded`).

## Auth and security

- A single admin: `ADMIN_USERNAME` + `ADMIN_PASSWORD_HASH` (bcrypt), overridable through `PUT /admin/profile` (stored in `system_settings`). HS256 JWT, lifetime `ACCESS_TOKEN_EXPIRE_MINUTES` (60).
- `POST /auth/token` protected by `login_rate_limiter` (`core/login_rate_limit.py`, 5 attempts / 15 min by default, key `client_key(request, username)`; the passkey shares this limiter, TOTP has `totp_rate_limiter`).
- TOTP two-factor authentication (routes `controllers/systeme/totp.py`, logic `services/systeme/totp.py`, calculation, `is_enabled` and `create_mfa_token` in `core/totp.py`): when enabled, `POST /auth/token` only returns an `mfa_token`; the session is obtained through `POST /auth/totp/login`. Not required for the passkey.
- `config.py` refuses a placeholder `SECRET_KEY` or one under 32 characters in **all** environments except `test`; with `APP_ENV=prod` it also refuses a placeholder admin hash and CORS `*`.
- Changing the username or password through `PUT /admin/profile` requires `current_password` (400 otherwise, never 401/403: the API client logs out on those codes); password ≥ 8 characters.
- JWT: PyJWT (`jwt`), HS256. `POST /auth/refresh` renews a still-valid session token (never an MCP token) keeping `auth_time`; refused (401) beyond `SESSION_MAX_HOURS` (12 h) since login. The frontend calls it when less than 15 min remain (`lib/api.ts`).
- Never commit `*.db` (ignored by `.gitignore`).

## Tests

- `PYTHONPATH=. python3.11 -m pytest tests -q` from `backend/` (~950 tests, ~2 min 40 serially; `-n auto` via pytest-xdist: ~80 s, used by `make test`, `make coverage` and CI). `make test` detects the interpreter (`backend/.venv` created by `uv sync`, otherwise python3.12/3.11); `venv_new` is Python 3.14 without pytest.
- Coverage: `make coverage` (`pytest --cov`, config `backend/.coveragerc`) fails under the `fail_under` threshold (93 % of lines on 2026-11-01, measured 93.75 %). Ratchet: never lower it, raise it when coverage improves; checked by `make validate` and CI.
- Fixtures (`tests/conftest.py`): `db_session` (temporary SQLite per test, `Base.metadata.create_all`) and `client` (TestClient, overrides `get_db` and `get_current_user` → `"admin"`, rate limiter reset). Check the database state after the API call.
- One test per fixed bug / added feature, named `tests/<domain>/test_<subject>.py`. Performance fix: a test that bounds the number of SQL queries with the `measure_queries` fixture (`measure_queries(lambda: client.get(...))` → `(result, count)`) on ≥ 1,000 rows; `tests/garde_fous/test_async_endpoints.py` forbids an `async def` without `await` in `controllers/`.
- Layout: one folder per domain, like `services/`: `budget/`, `comptes/`, `investissement/`, `analytics/`, `audit/`, `systeme/` (auth, security, MCP, demo, notifications). Plus `garde_fous/` (architecture, sizes, migrations, OpenAPI routes, pinning, network) and `non_regression/` (snapshots and cross-cutting audit batches). The `domain`, service and route tests of one subject go in the same folder; `conftest.py` and `snapshots/` stay at the root of `tests/`. No `__init__.py`: file names must stay unique; an import between test files goes through `tests.<domain>.test_x`.
- `tests/non_regression/test_analytics_snapshots.py` freezes the output of all analytics routes (demo at a frozen date), `tests/non_regression/test_portfolio_snapshots.py` that of the portfolio routes (same demo + a securities account with Zero Point): a difference is a bug, never regenerate the snapshots to make the test pass (procedure: `numera-testing` skill). `tests/garde_fous/test_openapi_routes.py` freezes the list of routes (method + path).
