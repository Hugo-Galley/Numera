# Frontend — conventions (React 19 / Vite / TypeScript / Tailwind / shadcn)

Complements the root `CLAUDE.md`. Procedures: `numera-frontend` skill. The frontend is **purely presentational**: no KPI is computed here, everything comes from `/analytics/*`. Accepted exceptions (presentation, not a KPI): percentage shares of a chart, sorting, and calculations on the rows already loaded in a list. Still to move to the backend: variations on the Comparison page, the drill-down total (shown only if the list is not truncated at 500), euro-fund / unit-linked split of a life-insurance policy, yearly subtotals of the loan schedule, total value of filtered positions, average in search mode.

The user interface is translated (French reference, English, Spanish; see § Languages). Tests run in French, so UI labels quoted below (in quotes, French) are the literal strings that tests query by name.

## Structure

- `App.tsx`: react-router v7. `/login` public; the rest under `ProtectedRoute` + `AppLayout` (Sidebar, Omnibox). Routes (pages lazy-loaded with `React.lazy`): `/`, `/accounts`, `/accounts/:id`, `/savings`, `/investments`, `/month/{bilan,revue,comparaison}` (`MonthHub.tsx`; bilan = `MonthlyReport.tsx`, sections in `components/monthly-report/`; revue = `MonthReview.tsx`, pop-up `components/month-review/MonthReviewPopup` on the Dashboard), `/recurring` ("Échéances", i.e. due dates, tabs through `?tab=` including `calendar` = embedded `Calendar.tsx` and `salary` = `components/recurring/IncomeTab`: Salary or Benefits received through `?vue=aides`), `/audit` (Action Center, urgent-actions badge in the Sidebar), `/wrapped` (yearly review, `Wrapped.tsx`: recap + full-screen story `components/wrapped/WrappedStory`), `/tools`, `/tax` (Taxation), `/classement` (categories, tags, merchants, rules), `/settings` (4 tabs: general, notifications, security, data; old `?tab=` values redirected in `Settings.tsx`). Old addresses `/report`, `/month-review`, `/comparison`, `/calendar` are redirected (`RedirectKeepingSearch`). Unknown route (logged in) → `NotFound` page inside the layout, address unchanged, link "Retour au tableau de bord" (back to the dashboard). Sidebar: 3 fixed groups, 12 entries; a new page goes first into an existing tab if it belongs there.
- Cap of 350 lines per file (empty baseline, `make check-size`). A page that is too long becomes a `pages/<Page>/` folder with `index.tsx` (composition, early returns), one component per section / dialog receiving `ctx`, `use*.ts` hooks for state and loading (model: `pages/AccountDetail/`); a big component becomes `components/<domain>/<Component>/` whose `index.tsx` keeps the same export. A small overflow is fixed by moving a utility or sub-component into a neighbouring file (e.g. `analytics/sankeyLayout.ts`).
- `providers/`: `AuthProvider` (token in `localStorage`, `useAuth()`), `UIProvider` (theme, privacy mode `isPrivacyMode`, omnibox state), `ConfirmProvider` (`useConfirm()`, confirmation dialog).
- `lib/api/<domain>.ts` (`accounts`, `analytics`, `classement`, `investments`, `loans`, `monthReview`, `recurring`, `reimbursements`, `savings`, `settings`, `transactions`): one function per route (`getAccounts`, `patchAccountsById`, `getTransactions(query)`…), generic `<T>` at the call site, `query` ("?a=1") appended as is to the URL. Pages and hooks go through them; a new route adds its function there. They rely on `lib/api.ts`: `api.get/post/put/patch/delete` + `apiFetch`. Adds the Bearer; on `401` (or `403` outside `/auth/token`) clears the session and redirects to `/login`. `API_BASE`: `VITE_API_BASE` if set, otherwise `http://localhost:8001` under the Vite dev server, otherwise `/api` (build served by nginx, even on localhost → `backend:8001`). Errors are thrown as `ApiError(status, message, detail)`. **Read cache** (`lib/apiCache.ts`, TanStack Query): `api.get` serves the same URL for 30 s without a request (simultaneous reads de-duplicated, a copy is returned: it can be modified), any write (`post/put/patch/delete/upload`), logout or 401 invalidates it. A "Actualiser" (refresh) / "Réessayer" (retry) button or a `reload()` that re-reads without writing must call `resetApiCache()` first, otherwise it would serve the same response again.
- Bundle splitting: `build.rolldownOptions.output.codeSplitting.groups` in `vite.config.ts` (Vite 8 / Rolldown: `rollupOptions` and `manualChunks` are deprecated; chunks `vendor-react`, `-router`, `-radix`, `-charts`, `-date`, `-ui`). Charts (`vendor-charts`, ~140 KB gzip) must not appear in the `modulepreload` of `dist/index.html`. Pitfall: with `includeDependenciesRecursively: false` (intended, otherwise the group pulls in shared modules and `vendor-charts` ends up preloaded at entry), the dependencies of recharts 3 (d3, es-toolkit, Redux Toolkit / react-redux / reselect / immer, eventemitter3…) must be **listed explicitly** in the `vendor-charts` group, otherwise they fall into a page chunk and create an import cycle: the build passes, tests and `vite dev` too, but production crashes (`TypeError: Ie is not a function` on chart pages). After any change to the groups or a new dependency: `npm run build`, check that `vendor-charts` (~150 KB gzip) is not in the `modulepreload`s of `dist/index.html`, then open a chart page in the **build** (`vite preview`), not only in dev. Vite and `@vitejs/plugin-react` go up together (plugin 6 requires `vite@^8`); Node ≥ 20.19 / 22.12 required.
- `hooks/useSubmit.ts`: protects an async handler against double submission (`const [handleX, busy] = useSubmit(async () => …)`, button `disabled={busy}`). `components/layout/ErrorBoundary.tsx` (global and per route) and `ErrorState.tsx` (message + "Réessayer": a failed load must never look like "no data"). `lib/storage.ts`: `safeStorage` instead of `localStorage` (never throws).
- `types/` (a single file: `diversity.ts`): API types are mostly defined locally in pages/components.
- `lib/utils.ts`: `formatCurrency(value, currency="EUR")` (locale of the interface: `fr-FR` or `en-GB`), `cn()`, `isTokenExpired()`.
- **Languages (i18n)**: French (reference), English and Spanish, chosen in Settings → General → Display (dropdown with flags), remembered per device (`localStorage`, key `language`), otherwise the browser language if supported (`fr*`, `en*`, `es*`), otherwise English. `src/i18n/`: `index.ts` (`i18next` + `react-i18next` init, `setLanguage`, `detectLanguage`), `locales/<fr|en|es>/<namespace>.json` (one catalogue per domain: `common`, `nav`, `auth`, `settings`, `dashboard`, `accounts`, `accountDetail`, `transactions`, `import`, `loans`, `investments`, `omnibox`, `savings`, `recurring`, `reimbursements`, `month`, `classement`, `audit`, `tax`, `tools`, `wrapped`; a migrated domain = a new namespace to declare in `index.ts`), `locale.ts` (`appLocale()`, `dateLocale()`, `monthName()`, `monthShort()`, `percentSuffix()`; `LOCALES` table per language), `LanguageBoundary` (remounts the tree when the language changes). In a component: `const { t } = useTranslation("<namespace>")`, text through `t("key")` (keys are **typed** from the French: a typo fails `tsc`; plural `key_one` / `key_other` + `{ count }`; variables `{{name}}`; text with tags or a bold amount: `<Trans t={t} i18nKey="…" components={{ amount: <span className="…" /> }} />` and `<amount>{{value}}</amount>` in the catalogue; generic words (Add, Cancel, Save…): `common:actions.*`); outside a component (`lib/`, class, module constant): `i18n.t("key", { ns })` **at call time**, never in a constant evaluated at import (the language would be frozen): store a key and translate at display time (e.g. `Omnibox/types.ts` → `navigationName`). **Label computed in an object constant**: use getters (`get high() { return i18n.t(…) }`, see `Audit/types.ts`) to keep the `LABELS[key]` syntax without freezing the language. **Data values (type `Sortie`, generated notes, preset names) are never translated** (they are stored); only their display labels are. A `t` used in a `useEffect` / `useCallback` goes in its dependencies; do not name a local variable `t` (it shadows the function). **Never write `"fr-FR"` or `{ locale: fr }`**: use `appLocale()` / `dateLocale()` so that dates, months and amounts follow the language. Only the interface is translated: labels, categories, notes and merchants entered by the user stay as they are. **Adding a language**: its code in `LANGUAGES` and its resources (`i18n/index.ts`), a `locales/<code>/` folder (same files and keys as `fr`), an entry in `LOCALES` (`locale.ts`), its name in `LANGUAGE_NAMES` and its flag in `LANGUAGE_FLAGS` (`DisplayCard`); for the backend see `backend/CLAUDE.md`. Every new string goes in all catalogues (`i18n/catalogs.test.ts` checks, for each language, the same keys and the same `{{variables}}` as in French). Tests run in French (`test/support/setup.ts` resets `fr` before each test); an English test calls `setLanguage("en")` and resets `fr` afterwards. **State**: all the display produced by the frontend is translated (login, menus, settings, dashboard, accounts and account detail, CSV import, loans, investments, Omnibox, savings, due dates, reimbursements, month, classement, Action Center, taxation, tools, yearly review, shared charts, API-client error messages; the word `EFFACER` to type for a reset stays in French: it is the code the backend expects; default allocations and simulator presets keep their French names, being stored data values). **Language sent to the backend**: `apiFetch` attaches `Accept-Language: <interface language>` to every request and `setLanguage` clears the read cache (a cached server text would be in the old language). Notifications come from a background task without a header: the language choice is also saved server-side (`lib/serverLanguage.ts`, `PUT /notifications/settings {language}`, on click in Display and when opening the Notifications tab if the value differs). **Text coming from the backend** is translated by the backend (see `backend/CLAUDE.md`). A migrated page = a namespace, a domain commit.
- Contrast: `text-slate-400` (2.6:1) for icons and decorations only; a text element (`p`, `span`, `td`…) that uses it is raised to slate-500 by `styles.css`, but write `text-slate-500` from the start for any informative text.
- React 19: a new component receives `ref` as an ordinary prop (no more `forwardRef`); existing `forwardRef`s in `components/ui` stay valid (deprecated, convert only when touching the file). No `defaultProps`, `propTypes` or `ReactDOM.render`; `useRef` always takes an initial value; JSX through `React.JSX` (no more global `JSX` namespace). `package.json` forces `react-is` ^19 (`overrides`) so that `recharts` 3 (where `react-is` is a peer dependency) uses the same version as React. `react-simple-maps` 5: types shipped, no `hover`/`pressed` states in `style` (the `WorldMap` hover is in `styles.css`, classes `world-map-country*`).
- `components/ui/`: shadcn/Radix primitives (`button`, `card`, `dialog`, `table`, `tabs`, `select`, `sheet`, `sonner`, `skeleton`…). Do not modify them without need. Adding a component: `components.json` is configured for shadcn.
- `components/<domain>/`: `investments` (including `PortfolioSummary` computed value / reconciliation, `DividendsCard`, `HoldingsTable`), `dashboard` (KPIs, header, `tabs/` = Overview, History, Budgets, Insights, Investments, Merchants, Projections, Subscriptions), `investments`, `settings` (settings cards), `classement`, `import`, `audit`, `tools`, `analytics`, `layout`.

## Rules

- Import alias `@/` → `src/`.
- API calls only through `lib/api/<domain>.ts`: no direct `api.get/post/…` in pages and components (checked by `src/test/lib/api/noDirectApi.test.ts`); the JWT and 401 handling are centralised in `lib/api.ts`. Multipart uploads: `api.upload(endpoint, formData)` (does not send `Content-Type`, the browser sets the boundary, but adds the Bearer). File downloads: `api.download(endpoint)` → `Blob` (never `window.location`, which does not send the JWT). The `api.*` helpers default to `T = unknown` (the wrappers of `lib/api/<domain>.ts` provide the contract's type). **API contract**: `lib/api/generated/` (`openapi.json` exported from the backend, `schema.d.ts` generated by `openapi-typescript`) feeds `ApiResponse<"/accounts", "get">` and `ApiBody<"/accounts", "post">` (`lib/api/types.ts`). All the wrappers of `lib/api/<domain>.ts` are typed this way (default response `ApiResponse<path, method>`, body `ApiBody<…>`): a field renamed on the backend side makes `tsc` fail. An explicit generic at the call site (`getX<Foo>()`) bypasses this check: leave the default when the API type fits. A response without a JSON body (204) is typed `void`. Route or Pydantic schema changed → `make api-contract` and commit; CI fails otherwise.
- Data fetching: in the page, or in a dedicated hook when it is heavy (`components/dashboard/useDashboardData.ts` loads the whole Dashboard with a `safeLoad` per endpoint so that one failure does not block the others). Sub-components receive props.
- Strict TypeScript, **zero `any`** (ESLint `@typescript-eslint/no-explicit-any` as an error, outside `components/ui/` and `lib/api/generated/`): API types through `ApiResponse` / `ApiBody` (aliases in a neighbouring `types.ts`), `catch (err)` + `errorMessage(err, fallback)`, `unknown` + a type guard for free-form data. If the OpenAPI contract does not declare a field (e.g. `price` in the results of `/market/search`, `metadata` / `samples` of the Action Center), keep a minimal local type with a comment saying so, without touching the backend.
- Amounts: always `formatCurrency`. Privacy mode: `lib/privacyScanner.ts` automatically detects amounts (currency, thousands, decimals; DOM, chart SVG, tooltips, inputs) and applies `.privacy-masked` to them; no more reveal on hover (an input field is revealed on focus). `amount-blur` remains usable to force masking of an undetectable value (e.g. a percentage). `data-privacy-ignore` excludes an area. Do not use `.amount-value` (it does not exist).
- Dates: never `toISOString()` (UTC) for an entered field. `lib/dates.ts`: `nowLocalInput`/`todayLocal` (initial values), `toInputValue` (API → field), `toNaiveLocal` (field → API, without `Z`), `startOfDayParam`/`endOfDayParam` for filters (the last day included). The database stores naive datetimes displayed as is.
- Confirmation before a destructive action: `const confirm = useConfirm()` (`providers/ConfirmProvider`) then `if (!(await confirm("…"))) return`; never `window.confirm()` / `alert()`.
- Performance: `numera-performance` skill. A "Actualiser" button / `reload()` that re-reads without writing calls `resetApiCache()` (test that counts requests); never `queryClient.clear()`; after a dependency change, check the `modulepreload`s of `dist/index.html` and the gzip size of the initial load.
- An effect that fires on specific values (account change, month change, on mount) but calls a loading function recreated on every render: the call goes through `useEffectEvent` (`const reload = useEffectEvent(() => { loadData() }); useEffect(() => { reload() }, [month, year])`), never through a `// eslint-disable` nor by adding the function to the dependencies (reload loop). A `useState` setter is added as is to the dependencies.
- Loading: a page that changes month/account ignores stale responses (a `cancelled` flag or a request number) and empties its data before reloading; `errorMessage(error, fallback)` (`lib/utils`) displays the server's detail.
- User feedback: `toast.success` / `toast.error` (`sonner`) after every mutation; `Skeleton` while loading; empty state with icon + action.
- Light / dark theme: `UIProvider` (`theme` = light|dark|system, `localStorage`, `dark` class on `<html>`, set before React by the `index.html` script). Tailwind palettes (slate, emerald, rose…, `white`) are CSS variables (`src/theme-colors.css`, Tailwind 3 RGB values kept by hand; `styles.css` wires them to `--color-*` through `@theme inline`, which lets `.theme-island` redefine them) **inverted in dark mode**: write the usual classes (`bg-white`, `text-slate-900`, `bg-emerald-50`) and **never a `dark:` variant** on these colours (it would invert twice). Hexadecimal greys in chart SVG attributes are re-wired by `styles.css`; a new hard-coded neutral colour must be one of these slate shades. A block deliberately dark in both themes (hero card `bg-slate-900 text-white`, Wrapped story, treemap) takes the `theme-island` class: it keeps the light palette in dark mode instead of turning white. Inline colour background (category/tag colour): `text-white` on it stays white in dark mode; for an inline neutral fallback, write `rgb(var(--c-slate-500))` rather than a hexadecimal. Recharts tooltips (default or custom `content`) are raised in dark mode by `styles.css`, nothing to do in the component.
- Icons `lucide-react`. Charts `recharts` (Slate / Emerald / Rose / Amber palette; tooltips and legends mandatory; clickable elements for drill-down: `useDrilldown().openDrilldown({month, year, label, categoryId | merchantName, accountId})` opens the `components/transactions/DrilldownSheet` panel mounted in `AppLayout`, filters carried by the `?dd_*` URL). Sankey/treemap in `components/analytics`. Recharts 3: the `formatter` of `Tooltip` receives `ValueType` (number, string or array), so an amount formatter is written `formatter={numberFormatter((v: number) => …)}` (`lib/chartTooltip.ts`); `Tooltip` and `Legend` sort series by name by default, hence `itemSorter={keepSeriesOrder}` (Tooltip) and `itemSorter={null}` (Legend) to keep the chart's order; a custom tooltip types its props with `TooltipContentProps`; an `onClick` on `Pie`/`Bar` finds the entry by its index (`data[index]`), not by `data.id`.
- Forms: local state (`useState` + `useSubmit`), manual validation before the API call. `react-hook-form`, `zod` and `components/ui/form` were removed (never used); reintroducing them requires justification.
- Dead code: `npm run knip` (`make knip`, `knip.json`) fails on an unused file, dependency, export or type outside `components/ui/`; zero baseline, delete rather than ignore. An export used only in its own file is tolerated (`ignoreExportsUsedInFile`).
- Mobile (375 px): every new page or component follows `docs/MOBILE.md` (`MobileNav` navigation, cards below `md`, 16 px fields, 40 px targets). Desktop (≥ md) must not change.
- New navigable feature → add it to the Sidebar and to the Omnibox (⌘K).

## Verification

`cd frontend && npm test && npm run build` (or `make test-front`, included in `make validate` and CI). `npm test` = `vitest run` (`npm run test:watch` for continuous mode, `npm run coverage` = tests + v8 coverage with ratchet thresholds in `vitest.config.ts` (statements 82 %, lines 83 %, functions 74 %, branches 67 % on 2026-11-12; a file no test loads is counted at 0 by v8, so a new page without a test lowers the measure): never lower them, raise them when coverage improves; checked by `make coverage`, `make validate` and CI). `npm run build` = `npm run typecheck && vite build`; `typecheck` runs `tsc` on the app (`tsconfig.json`, which excludes tests) then on the tests (`tsconfig.test.json`, `vitest/globals` and jest-dom types) and on the E2E tests (`tsconfig.e2e.json`). The project has 0 TypeScript errors: do not introduce any. Lint: `make lint-front` / `npm run lint` (ESLint 9 flat config `frontend/eslint.config.js`: typescript-eslint recommended, `react-hooks/rules-of-hooks` and `exhaustive-deps`, unused variables; included in `make validate` and CI). Errors always fail; the baseline `frontend/eslint-baseline.json` is empty (0 warnings since 2026-11-11): a new warning fails, it gets fixed, it is not added to the baseline (`node scripts/check-lint.mjs --write-baseline` only serves to lower it). No `eslint-disable` without a written reason. Playwright E2E (about a hundred journeys, including a `security` profile with a separate stack for 2FA / passkeys / MCP tokens / backup / notifications, blocked in the demo: login, accounts, transactions, import, ranking, month, investments, settings, mobile… and a console / 5xx guard on every page) is separate: `make test-e2e`, the `e2e` job in CI (a single job), details and how to add a scenario in `frontend/e2e/README.md`; a scenario starts from `e2e/fixtures.ts`, not from `@playwright/test`. MSW 3: the "request without a handler" safeguard goes through `onUnhandledFrame` (`src/test/support/setup.ts`; the former `onUnhandledRequest` is ignored without an error) and `FormData` bodies are encoded as multipart before `fetch`. Additional manual check: privacy mode (eye), dark theme, mobile responsiveness.

Tests (Vitest + jsdom + Testing Library + MSW; config `frontend/vitest.config.ts`, `TZ=Europe/Paris`, globals `describe/it/expect/vi`).
- **All tests live under `src/test/`**, never next to the code: a test mirrors the path of its source file (`src/pages/AccountDetail/UpcomingCard.tsx` → `src/test/pages/AccountDetail/UpcomingCard.test.tsx`, `src/lib/utils.ts` → `src/test/lib/utils.test.ts`); a domain's translation tests (`*.i18n.test.tsx`) are in the domain's folder. Shared tooling is in `src/test/support/` (never imported by the app, absent from the build). Imports through the `@/…` alias, never relative. `src/test/structure.test.ts` fails if a `*.test.ts(x)` is created elsewhere.
- Rendering: `renderWithProviders(ui, { route, auth })` from `@/test/support/render` (UIProvider + AuthProvider + ConfirmProvider + MemoryRouter + Toaster; also returns `user` = `userEvent.setup()`), never a bare `render` for a component that depends on a provider. `auth: true` sets a JWT valid for one hour (`makeToken({ expInMinutes })` from `@/test/token`, negative = expired). `WorkTimeProvider` and the routes of `App.tsx` are not mounted: add them in the test that needs them (`App.test.tsx` renders `<App />` with `stubPage` dummy pages; `LocationDisplay` from `@/test/LocationDisplay` displays the current address to check a redirect).
- DOM queries by role and (French) label (`getByRole("button", { name: "Enregistrer" })`), not by CSS class nor `data-testid` except as a last resort.
- API simulated at network level by MSW (do not mock `lib/api.ts`): default handlers in `src/test/support/handlers/<domain>.ts` (same split as `lib/api/`, plus `auth`: `/admin/profile`, `/auth/refresh`, `/health`), URL through `apiUrl("/accounts")`, test-specific response through `server.use(...)` (`@/test/server`). Any request without a handler fails the test, even if the component swallows the error.
- API client: `recordRequests()` (`@/test/support/recordRequests`) sets a catch-all handler and records method, path, query, headers and body; `describeApiCases(domain, module, cases)` (`@/test/support/apiCases`) checks the function → request table of a `lib/api/<domain>.ts` (a function added without a case fails the test). `lib/api/routes.test.ts` checks every called route against `backend/tests/snapshots/openapi_routes.json`.
- Data: factories `makeAccount`, `makeTransaction`, `makeCategory`, `makeProfile`, `makeActionCenter` (`@/test/support/factories`), overridden field by field.
- Between two tests: DOM unmounted, handlers reset, `localStorage` / `sessionStorage` emptied. jsdom polyfills (`matchMedia`, `ResizeObserver`, `IntersectionObserver`, `scrollIntoView`, `scrollTo`, pointer capture) in `src/test/support/setup.ts`.
- Today's date: `vi.useFakeTimers({ toFake: ["Date"] })` + `vi.setSystemTime(...)`.
- After a mutation, check the request received by MSW (method, body) **and** what is displayed (toast, updated row).
- A fixed frontend bug = a failing test first. No committed `it.skip` / `it.only`.
