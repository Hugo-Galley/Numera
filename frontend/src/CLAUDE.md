# Frontend — conventions (React 18 / Vite / TypeScript / Tailwind / shadcn)

Complète le `CLAUDE.md` racine. Procédures : skill `numera-frontend`. Le frontend est **purement présentatif** : aucun KPI calculé ici, tout vient de `/analytics/*`.

## Structure

- `App.tsx` : react-router v7. `/login` public ; le reste sous `ProtectedRoute` + `AppLayout` (Sidebar, Omnibox). Routes (pages chargées à la demande, `React.lazy`) : `/`, `/accounts`, `/accounts/:id`, `/savings`, `/investments`, `/month/{bilan,revue,comparaison}` (`MonthHub.tsx` ; bilan = `MonthlyReport.tsx`, sections dans `components/monthly-report/` ; revue = `MonthReview.tsx`, pop-up `components/month-review/MonthReviewPopup` sur le Dashboard), `/recurring` (« Échéances », onglets `?tab=` dont `calendar` = `Calendar.tsx` embarqué et `salary` = `components/recurring/IncomeTab` : Salaire ou Aides perçues via `?vue=aides`), `/audit` (Centre d'Actions, pastille d'actions urgentes dans la Sidebar), `/wrapped` (bilan annuel, `Wrapped.tsx` : récap + story plein écran `components/wrapped/WrappedStory`), `/tools`, `/tax` (Fiscalité), `/classement` (catégories, tags, marchands, règles), `/settings` (4 onglets : general, notifications, security, data ; anciens `?tab=` redirigés dans `Settings.tsx`). Anciennes adresses `/report`, `/month-review`, `/comparison`, `/calendar` redirigées (`RedirectKeepingSearch`). Route inconnue → `/`. Sidebar : 3 groupes fixes, 12 entrées ; une nouvelle page va d'abord dans un onglet existant si elle s'y rattache.
- Plafond de 350 lignes par fichier (baseline vide, `make check-size`). Une page trop longue devient un dossier `pages/<Page>/` avec `index.tsx` (composition, retours anticipés), un composant par section / dialogue recevant `ctx`, hooks `use*.ts` pour l'état et le chargement (modèle : `pages/AccountDetail/`) ; un gros composant devient `components/<domaine>/<Composant>/` dont `index.tsx` garde le même export. Un petit dépassement se règle en sortant un utilitaire ou un sous-composant dans un fichier voisin (ex. `analytics/sankeyLayout.ts`). Plan et générateurs : `docs/superpowers/plans/2026-10-29-phase-5-frontend.md`.
- `providers/` : `AuthProvider` (token en `localStorage`, `useAuth()`), `UIProvider` (thème, mode confidentialité `isPrivacyMode`, état de l'omnibox), `ConfirmProvider` (`useConfirm()`, boîte de confirmation).
- `lib/api/<domaine>.ts` (`accounts`, `transactions`, `classement`, `recurring`, `savings`, `investments`, `analytics`) : une fonction par route (`getAccounts`, `patchAccountsById`, `getTransactions(query)`…), générique `<T>` à l'appel, `query` (« ?a=1 ») ajouté tel quel à l'URL. Les pages et hooks passent par elles ; une nouvelle route y ajoute sa fonction. Elles reposent sur `lib/api.ts` : `api.get/post/put/patch/delete` + `apiFetch`. Ajoute le Bearer ; sur `401` (ou `403` hors `/auth/token`) vide la session et redirige vers `/login`. `API_BASE` : `VITE_API_BASE` si défini, sinon `http://localhost:8001` sous le serveur de dev Vite, sinon `/api` (build servi par nginx, même sur localhost → `backend:8001`). Erreurs levées en `ApiError(status, message, detail)`.
- `hooks/useSubmit.ts` : protège un handler async contre la double soumission (`const [handleX, busy] = useSubmit(async () => …)`, bouton `disabled={busy}`). `components/layout/ErrorBoundary.tsx` (global et par route) et `ErrorState.tsx` (message + « Réessayer » : un chargement qui échoue ne doit jamais ressembler à « pas de données »). `lib/storage.ts` : `safeStorage` à la place de `localStorage` (ne lève jamais).
- `types/` (un seul fichier : `diversity.ts`) : les types d'API sont majoritairement définis localement dans les pages/composants.
- `lib/utils.ts` : `formatCurrency(value, currency="EUR")` (locale `fr-FR`), `cn()`, `isTokenExpired()`.
- `components/ui/` : primitives shadcn/Radix (`button`, `card`, `dialog`, `table`, `tabs`, `select`, `sheet`, `sonner`, `skeleton`…). Ne pas les modifier sans nécessité. Ajouter un composant : `components.json` est configuré pour shadcn.
- `components/<domaine>/` : `investments` (dont `PortfolioSummary` valeur calculée / rapprochement, `DividendsCard`, `HoldingsTable`), `dashboard` (KPI, header, `tabs/` = Overview, History, Budgets, Insights, Investments, Merchants, Projections, Subscriptions), `investments`, `settings` (cartes de réglages), `classement`, `import`, `audit`, `tools`, `analytics`, `layout`.

## Règles

- Alias d'import `@/` → `src/`.
- Appels API uniquement via `lib/api/<domaine>.ts` (ou `api` de `@/lib/api` dans du code non encore migré : le JWT et la gestion du 401 y sont centralisés). Uploads multipart : `api.upload(endpoint, formData)` (n'envoie pas `Content-Type`, le navigateur fixe le boundary, mais ajoute le Bearer). Téléchargements de fichiers : `api.download(endpoint)` → `Blob` (jamais `window.location`, qui n'envoie pas le JWT). Les helpers `api.*` ont `T = any` par défaut : typer le générique quand le payload est connu.
- Récupération de données : dans la page, ou dans un hook dédié quand elle est lourde (`components/dashboard/useDashboardData.ts` charge tout le Dashboard avec un `safeLoad` par endpoint pour qu'un échec n'en bloque pas d'autres). Les sous-composants reçoivent des props.
- TypeScript strict. Le code existant utilise encore `any` pour les réponses API ; dans du code nouveau, déclarer des types (`interface`) pour les payloads.
- Montants : toujours `formatCurrency`. Mode confidentialité : `lib/privacyScanner.ts` détecte automatiquement les montants (devise, milliers, décimales ; DOM, SVG des graphiques, infobulles, inputs) et leur pose `.privacy-masked` ; plus de dévoilement au survol (un champ de saisie se dévoile au focus). `amount-blur` reste utilisable pour forcer le masquage d'une valeur non détectable (ex. pourcentage). `data-privacy-ignore` exclut une zone. Ne pas utiliser `.amount-value` (n'existe pas).
- Dates : jamais `toISOString()` (UTC) pour un champ saisi. `lib/dates.ts` : `nowLocalInput`/`todayLocal` (valeurs initiales), `toInputValue` (API → champ), `toNaiveLocal` (champ → API, sans `Z`), `startOfDayParam`/`endOfDayParam` pour les filtres (le dernier jour inclus). La base stocke des datetimes naïfs affichés tels quels.
- Confirmation avant une action destructive : `const confirm = useConfirm()` (`providers/ConfirmProvider`) puis `if (!(await confirm("…"))) return` ; jamais `window.confirm()` / `alert()`.
- Chargements : une page qui change de mois/compte ignore les réponses obsolètes (drapeau `cancelled` ou numéro de requête) et vide ses données avant de recharger ; `errorMessage(error, repli)` (`lib/utils`) affiche le détail du serveur.
- Retours utilisateur : `toast.success` / `toast.error` (`sonner`) après chaque mutation ; `Skeleton` pendant le chargement ; état vide avec icône + action.
- Thème clair / sombre : `UIProvider` (`theme` = light|dark|system, `localStorage`, classe `dark` sur `<html>`, posée avant React par le script d'`index.html`). Les palettes Tailwind (slate, emerald, rose…, `white`) sont des variables CSS (`src/theme-colors.css`, généré par `scripts/gen-theme-colors.cjs`) **inversées en sombre** : écrire les classes habituelles (`bg-white`, `text-slate-900`, `bg-emerald-50`) et **jamais de variante `dark:`** sur ces couleurs (elle s'inverserait deux fois). Les gris en hexadécimal dans les attributs SVG des graphiques sont rebranchés par `styles.css` ; une nouvelle couleur neutre en dur doit être l'une de ces teintes ardoise. Un bloc volontairement sombre dans les deux thèmes (carte héros `bg-slate-900 text-white`, story Wrapped, treemap) prend la classe `theme-island` : il garde la palette claire en sombre au lieu de devenir blanc. Fond de couleur inline (couleur de catégorie/tag) : `text-white` dessus reste blanc en sombre ; pour un repli neutre inline, écrire `rgb(var(--c-slate-500))` plutôt qu'un hexadécimal. Les infobulles Recharts (défaut ou `content` perso) sont surélevées en sombre par `styles.css`, rien à faire dans le composant.
- Icônes `lucide-react`. Graphiques `recharts` (palette Slate / Emerald / Rose / Amber ; tooltips et légendes obligatoires ; éléments cliquables pour drill-down : `useDrilldown().openDrilldown({month, year, label, categoryId | merchantName, accountId})` ouvre le panneau `components/transactions/DrilldownSheet` monté dans `AppLayout`, filtres portés par l'URL `?dd_*`). Sankey/treemap dans `components/analytics`.
- Formulaires : `react-hook-form` + `zod` (+ `@hookform/resolvers`) avec `components/ui/form`.
- Mobile (375 px) : toute nouvelle page ou composant suit `docs/MOBILE.md` (navigation `MobileNav`, cartes sous `md`, champs 16 px, cibles 40 px). Le bureau (≥ md) ne doit pas changer.
- Nouvelle fonctionnalité navigable → l'ajouter à la Sidebar et à l'Omnibox (⌘K).

## Vérification

`cd frontend && npm test && npm run build` (ou `make test-front`, inclus dans `make validate` et la CI). `npm test` = `vitest run` (`npm run test:watch` en continu, `npm run coverage` pour la couverture v8, sans seuil pour l'instant). `npm run build` = `npm run typecheck && vite build` ; `typecheck` passe `tsc` sur l'app (`tsconfig.json`, qui exclut les tests) puis sur les tests (`tsconfig.test.json`, types `vitest/globals` et jest-dom). Le projet est à 0 erreur TypeScript : ne pas en introduire. Types manquants : `types/react-simple-maps.d.ts`. Pas de lint frontend. Contrôle manuel en plus : mode confidentialité (œil), thème sombre, responsive mobile.

Tests (Vitest + jsdom + Testing Library + MSW ; config `frontend/vitest.config.ts`, `TZ=Europe/Paris`, globals `describe/it/expect/vi`). Plan par lots : `docs/superpowers/plans/2026-10-30-tests-frontend.md`.
- Fichier `X.test.ts(x)` à côté du fichier testé. Outils partagés dans `src/test/` (jamais importés par l'app, absents du build).
- Rendu : `renderWithProviders(ui, { route, auth })` de `@/test/render` (UIProvider + AuthProvider + ConfirmProvider + MemoryRouter + Toaster ; renvoie aussi `user` = `userEvent.setup()`), jamais un `render` nu pour un composant qui dépend d'un provider. `auth: true` pose un JWT valide une heure (`makeToken({ expInMinutes })` de `@/test/token`, négatif = expiré). `WorkTimeProvider` et les routes d'`App.tsx` ne sont pas montés : les ajouter dans le test qui en a besoin.
- Requêtes DOM par rôle et libellé français (`getByRole("button", { name: "Enregistrer" })`), pas par classe CSS ni `data-testid` sauf dernier recours.
- API simulée au niveau réseau par MSW (ne pas mocker `lib/api.ts`) : handlers par défaut dans `src/test/handlers/<domaine>.ts` (même découpage que `lib/api/`, plus `auth` : `/admin/profile`, `/auth/refresh`, `/health`), URL via `apiUrl("/accounts")`, réponse propre à un test via `server.use(...)` (`@/test/server`). Toute requête sans handler fait échouer le test, même si le composant avale l'erreur.
- Client API : `recordRequests()` (`@/test/recordRequests`) pose un handler attrape-tout et consigne méthode, chemin, query, en-têtes et corps ; `describeApiCases(domaine, module, cas)` (`@/test/apiCases`) vérifie la table fonction → requête d'un `lib/api/<domaine>.ts` (une fonction ajoutée sans cas fait échouer le test). `lib/api/routes.test.ts` confronte chaque route appelée à `backend/tests/snapshots/openapi_routes.json`.
- Données : fabriques `makeAccount`, `makeTransaction`, `makeCategory`, `makeProfile`, `makeActionCenter` (`@/test/factories`), surchargées champ par champ.
- Entre deux tests : DOM démonté, handlers réinitialisés, `localStorage` / `sessionStorage` vidés. Polyfills jsdom (`matchMedia`, `ResizeObserver`, `IntersectionObserver`, `scrollIntoView`, pointer capture) dans `src/test/setup.ts`.
- Date du jour : `vi.useFakeTimers({ toFake: ["Date"] })` + `vi.setSystemTime(...)`.
- Après une mutation, vérifier la requête reçue par MSW (méthode, corps) **et** ce qui s'affiche (toast, ligne mise à jour).
- Un bug frontend corrigé = un test rouge d'abord. Aucun `it.skip` / `it.only` commité.
